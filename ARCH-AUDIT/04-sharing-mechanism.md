# 04 - Sharing mechanism (bake, hash, stub, drift check, cache-busting)

Baseline: frozen tag `v0.6.14` = `383007c`; tree `v0.6.14-2-g834b6bb`.

Constraints this must satisfy (verified):
- **No-build web**: `web/` is uploaded verbatim (`web/ftps_deploy.py:73-86`),
  entry `web/index.html:211` uses literal relative ES-module imports; no
  bundler/npm anywhere.
- **PyInstaller desktop**: `build.ps1:182` bundles `--add-data "static;static"`,
  so anything under `static/` ships; `web/` never ships.
- **Manual cache discipline**: module tokens are `?v=N` literals in
  `web/index.html` / `web/app.js` (`web/app.js:11-17`); one data file uses a
  `CATALOG_TOKEN` + manifest pair guarded by `scripts/check_catalog_token.py`
  and mutation-proven by `tests/test_cache_tokens.py`.
- **Check wiring**: `scripts/check_js.py:18-35` dynamically loads
  `scripts/check_*.py` and hard-fails on a non-zero `main()`;
  `scripts/check_release.py:451-491` runs its `collect()/evaluate()` chain;
  `scripts/check_encoding.py:51-75` scans the whole repo.

## 1. Canonical tree and hash

- `core/*.js` are committed with **LF** line endings (repo rule; working tree is
  CRLF under `core.autocrlf=true`, committed blobs LF).
- Tree hash: sha256 over the sorted list of `relpath + "\0" + sha256(bytes)` of
  every `core/**/*.js`, computed on **CRLF->LF normalized bytes**. Normalization
  is mandatory: a raw working-tree hash would differ between checkouts.
- Manifest `core/core.manifest.json` (tracked):
  `{ "hash": "<16 hex>", "files": { "astro.js": "<64 hex>", ... }, "token": <int> }`.

## 2. Bake layout

`scripts/build_core.py` (new, run by hand or from `check_core.py --write`):

```
web/core/<hash>/<all core files>       byte-identical to core (LF-normalized)
web/core.js                            stable stub: export * from './core/<hash>/index.js';
static/js/core/<hash>/<all core files> byte-identical copy
static/js/core.js                      stable stub (same content)
core/core.manifest.json                tree hash + per-file hashes + stub token
```

- The stub path is the only stable core URL; the hashed directory is the
  immutable payload. This mirrors the catalog manifest idea
  (`web/catalog.manifest.json`) at directory granularity.
- `web/core.js` is imported by web modules as `./core.js?v=<token>`;
  `static/js/core.js` is imported token-less by desktop modules (no cache
  headers on the local server).
- Only the current hash directory is committed; stale ones are deleted in the
  same commit. Remote cleanup is manual because `uploadtree`
  (`web/ftps_deploy.py:231-242`) does not delete:
  `python web/ftps_deploy.py remove /astro/core/<oldhash> --yes` in the release
  checklist.

## 3. Entry stub contract

```
// GENERATED by scripts/build_core.py - do not edit.
export * from './core/<hash>/index.js';
```

- Exactly one `export *`; no logic, so the stub cannot drift from the hash
  semantically.
- `core/index.js` is the only public surface (see `03-core-api.md`); shells
  import the stub, never a hashed path directly. A source guard (section 5)
  fails on `./core/<hash>/` imports outside generated stubs.

## 4. Drift / integrity check

`scripts/check_core.py` (new), modeled on `scripts/check_catalog_token.py`
(`:36-37` token regex, `:53-94` hashing + git-HEAD hardening):

1. Recompute the normalized tree hash from `core/`; require it to equal
   `core/core.manifest.json.hash` (else: core changed, bake not re-run).
2. For every file in `manifest.files`: byte equality (normalized) against
   `web/core/<hash>/<file>` and `static/js/core/<hash>/<file>`.
3. Require exactly one `core/<hash>` directory on each side and that it matches
   `manifest.hash` (no stale hash dirs).
4. Require both stable stubs to contain `./core/<hash>/index.js`.
5. Require the `?v=` token on every `./core.js?v=N` import in `web/` to equal
   `manifest.token` (single token for all core importers; unlike per-module
   tokens, one token is correct because the stub is the only stable URL).
6. Forbidden-identifier guard on `core/`: `document`, `window`, `localStorage`,
   `sessionStorage`, `indexedDB`, `fetch(`, `XMLHttpRequest`, `import.meta.url`
   (unless a test-only helper), Node built-ins.
7. Re-implementation guard: fail if the moved concepts reappear outside
   `core/` - e.g. `profileSegments` defined in `static/js/` or `web/`,
   `function julianDay` outside core, `moonPenalty` outside core. The list
   starts with exactly the functions moved in the current phase and grows per
   phase, keeping the guard truthful.
8. Git-diff hardening (same pattern as the catalog check): if `core/` bytes
   differ from `git show HEAD:core/...`, the bake artifacts and manifest must
   differ too in the same working tree, and the stub token must have been
   bumped if the hash changed.

Wiring:
- `check_core.py` is auto-loaded by `check_js.py` (its glob of `scripts/check_*.py`,
  `scripts/check_js.py:18-35`), so `check_js.py` fails on drift.
- `check_release.py` adds one `check_core` finding to its `evaluate()` chain
  (release packages must carry a consistent bake; `build.ps1` bundles `static/`
  so a stale `static/js/core/<hash>` would ship silently otherwise).
- `check_encoding.py` covers the generated files automatically (new text files).
- New tests `tests/test_core_drift.py` copy the tree to tmp and mutate
  (core byte, baked byte, stub hash, manifest hash, token) and assert
  `check_core.py` is non-zero for each mutation - mirroring
  `tests/test_cache_tokens.py:40-77`.

## 5. Cache-busting rules after core

- Core change -> new hash -> new directory (new URLs for every core file).
- The stable stub `web/core.js` changes bytes; its importers
  (`web/app.js`, `web/nightrank.js`, `web/horizon.js`, ...) already carry
  `?v=` tokens, so a core change bumps `core.js?v=N` in the same commit - the
  drift check enforces `manifest.token == N` (rule 5). `web/index.html`'s
  `app.js?v=` still bumps only when `app.js` itself changes.
- `web/catalog.json` token discipline is unchanged (catalog is data, not code).
- Desktop: no tokens; the hashed directory means a stale `static/js/core.js`
  in a browser cache is impossible locally, and the exe is versioned per
  release anyway.
- Immutability means the hashed directory can be served with long cache; only
  the stub is short-lived. No `no-store` anywhere (AGENTS rule).

## 6. Build-time Node

- `tests/js/*.mjs` already import JS directly and run under Node
  (`tests/test_js_parity.py:28-69`); after the move they import `core/` instead
  of the twins, so the same core runs in tests.
- If generated data must agree between Python and web (e.g. type labels row 27
  of `02-duplication-matrix.md`), `scripts/build_core.py --emit-data` can run
  `node scripts/gen_core_data.mjs` (imports `core/index.js`) and write JSON that
  Python reads/commits - the "Node runs the same core at build time" clause.
  No runtime Node is introduced; Node remains check/test/build-time only
  (current state: Node 24 available; all Node checks skip cleanly when absent,
  e.g. `scripts/check_js_syntax.py:233-240`).

## 7. Proof against the constraints

| Constraint | Why the mechanism holds |
|---|---|
| No-build web | Baked files are plain ES modules with literal relative imports; the stub is generated text. `uploadtree` copies `web/core/**` like any other file (`web/ftps_deploy.py:231-242`). No transpile step exists at serve/upload time. |
| Upload order | `index.html` still last (`web/ftps_deploy.py:73-86`); core files are assets, uploaded before it. Hashed dirs are referenced by the stub, so the stub must keep the existing "modules before index.html" order - already the case. |
| PyInstaller | `--add-data "static;static"` (`build.ps1:182`) includes `static/js/core/<hash>` and the stub with no new flags; `NightSeam.spec` is a stale artifact (AGENTS) and stays untouched. |
| Manual tokens | The only manual bump left is `core.js?v=N`, enforced by `check_core.py` rule 5/8; per-module tokens keep their existing rules. |
| Offline/testability | Core imports nothing; Node imports core directly; `check_encoding`/`check_js_syntax`/`check_js_imports` pick up generated files if they scan recursively (verify in Phase 1; `scripts/check_js_syntax.py:37-38` ROOTS and `scripts/check_js_imports.py` walk the trees). |
| Rollback | Reverting the phase commit restores the previous hash dir + stub + manifest in one commit (all tracked). No server/runtime migration is involved. |
